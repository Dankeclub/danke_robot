# 推流完整操作指南

基于现有服务器部署（88bill99.top + ZLMediaKit + Nginx），从 SSH 连接开始到成功推流的完整步骤。

---

## 架构概览

```
[树莓派 USB摄像头+麦克风]
    ↓ ffmpeg 采集编码（含镜像/翻转校正）
    ↓ RTMP 推流
[88bill99.top:25402 ZLMediaKit]
    ↓ 转封装 HTTP-FLV
    ↓ 127.0.0.1:25400/live/cam1.live.flv
[Nginx 443 HTTPS 反代]
    ↓ https://88bill99.top/live/cam1.live.flv
[微信小程序 / 浏览器 / 播放器拉流]
```

## 3. 摄像头画面校正

摄像头上下颠倒 + 左右镜像，用 ffmpeg 的 `-vf` 视频滤镜修正：

```bash
-vf "hflip,vflip"
```

| 滤镜 | 效果 |
|------|------|
| `hflip` | 左右镜像翻转 |
| `vflip` | 上下颠倒 |
| `hflip,vflip` | 两者叠加 = 180 度旋转 |
| `transpose=1` | 顺时针 90 度 |

## 4. 一键推流

低延时参数模板（已包含画面校正）：

```bash
ffmpeg \
  -fflags nobuffer \
  -flags low_delay \
  -thread_queue_size 512 \
  -f v4l2 -framerate 25 -video_size 1280x720 -i /dev/video0 \
  -thread_queue_size 512 \
  -f alsa -i default \
  -vf "hflip,vflip" \
  -c:v libx264 \
  -preset ultrafast \
  -tune zerolatency \
  -x264-params bframes=0:keyint=25:min-keyint=25:scenecut=0 \
  -pix_fmt yuv420p \
  -r 25 \
  -g 25 \
  -b:v 2000k \
  -maxrate 2000k \
  -bufsize 1000k \
  -c:a aac \
  -ar 44100 \
  -b:a 64k \
  -f flv \
  rtmp://88bill99.top:25402/live/cam1
```

> 推流地址格式：`rtmp://88bill99.top:25402/live/流名`  
> 流名可自定义，比如 `cam1`、`test`、`live001`

---

### 参数说明

| 参数 | 值 | 作用 |
|------|-----|------|
| `preset` | `ultrafast` | 最低编码耗时 |
| `tune` | `zerolatency` | 关闭编码器内部缓冲 |
| `bframes` | `0` | 关闭 B 帧，避免解码等待 |
| `keyint` | `25` | GOP=1秒（25fps下），关键帧间隔短=首屏快 |
| `b:v` | `2000k` | 视频码率 2Mbps |
| `b:a` | `64k` | 音频码率 64kbps，环境音够用 |
| `f flv` | — | 输出封装为 FLV，RTMP 标准格式 |
| `hflip,vflip` | — | 校正上下颠倒 + 左右镜像 |

## 6. 让推流不掉线（终端关了也不断）

### 6.1 临时方案：nohup（简单快速）

```bash
nohup ffmpeg \
  -fflags nobuffer \
  -flags low_delay \
  -thread_queue_size 512 \
  -f v4l2 -framerate 25 -video_size 1280x720 -i /dev/video0 \
  -thread_queue_size 512 \
  -f alsa -i default \
  -vf "hflip,vflip" \
  -c:v libx264 \
  -preset ultrafast \
  -tune zerolatency \
  -x264-params bframes=0:keyint=25:min-keyint=25:scenecut=0 \
  -pix_fmt yuv420p \
  -r 25 \
  -g 25 \
  -b:v 2000k \
  -maxrate 2000k \
  -bufsize 1000k \
  -c:a aac \
  -ar 44100 \
  -b:a 64k \
  -f flv \
  rtmp://88bill99.top:25402/live/cam1 \
  > /dev/null 2>&1 &
```

关终端不会断。缺点：机器重启后不会自动恢复。

### 6.2 正式方案：Systemd 服务（推荐，开机自启，挂了自动重启）

创建服务文件：

```bash
sudo tee /etc/systemd/system/push-cam1.service << 'SVC'
[Unit]
Description=推流 cam1 到 ZLMediaKit
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/bin/ffmpeg \
  -fflags nobuffer \
  -flags low_delay \
  -thread_queue_size 512 \
  -f v4l2 -framerate 25 -video_size 1280x720 -i /dev/video0 \
  -thread_queue_size 512 \
  -f alsa -i default \
  -vf "hflip,vflip" \
  -c:v libx264 \
  -preset ultrafast \
  -tune zerolatency \
  -x264-params bframes=0:keyint=25:min-keyint=25:scenecut=0 \
  -pix_fmt yuv420p \
  -r 25 -g 25 \
  -b:v 2000k -maxrate 2000k -bufsize 1000k \
  -c:a aac -ar 44100 -b:a 64k \
  -f flv \
  rtmp://88bill99.top:25402/live/cam1
Restart=always
RestartSec=5
User=pi
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
SVC
```

启用与管理：

```bash
# 加载服务
sudo systemctl daemon-reload

# 开机自启
sudo systemctl enable push-cam1

# 立即启动
sudo systemctl start push-cam1

# 查看状态
sudo systemctl status push-cam1

# 实时查看日志
sudo journalctl -u push-cam1 -f

# 停止
sudo systemctl stop push-cam1

# 重启
sudo systemctl restart push-cam1
```

### 6.3 备选：screen（交互式调试时好用）

```bash
sudo apt install -y screen
screen -S push          # 创建会话
# 运行 ffmpeg...
# Ctrl+A, D 分离
screen -r push          # 恢复
screen -ls              # 列出所有会话
```

## 7. 文件传输：本地 → 服务器

### 7.1 WinSCP（手动，可观测性好）

1. 下载安装 [WinSCP](https://winscp.net/)
2. 新建会话：
   - 协议：SFTP
   - 主机：`88bill99.top`
   - 端口：`30000`
   - 用户：`ljf`
   - 密码：服务器的 SSH 密码
3. 左侧本地目录，右侧服务器目录，拖拽即可上传
4. 文件传到服务器后，SSH 登入手动执行启动命令

### 7.2 VSCode SFTP 插件（保存即上传）

1. 在 VSCode 扩展市场搜索安装 **SFTP**（作者 liximomo / Natizyskunk）

2. 安装后在项目根目录按 `Ctrl+Shift+P` → 输入 `SFTP: Config`，生成 `.vscode/sftp.json`：

```json
{
  "name": "88bill99.top",
  "host": "88bill99.top",
  "port": 30000,
  "protocol": "sftp",
  "username": "ljf",
  "password": "你的密码",
  "remotePath": "/home/ljf/project/",
  "uploadOnSave": true,
  "useTempFile": false,
  "openSsh": false,
  "ignore": [".vscode", ".git", "node_modules", "__pycache__", "*.pyc"]
}
```

3. 之后每次 `Ctrl+S` 保存，文件自动上传到服务器对应目录
4. 右键文件/文件夹 → `SFTP: Upload` 手动上传
5. 右键远程目录 → `SFTP: Sync Local -> Remote` 批量同步

> 如果需要保持文件同步但想手动控制上传时机，把 `uploadOnSave` 设为 `false`。

### 7.3 工作流程：改代码 → 传文件 → 手动起服务

```
本地 VSCode 写代码
    ↓ Ctrl+S 保存 → SFTP 插件自动上传
服务器 /home/ljf/project/ 有最新文件
    ↓ SSH 连上去手动执行
nohup python app.py > /dev/null 2>&1 &
    ︙ 或者
systemctl restart my-service
```

这种方式的好处是每一步你都看得见、可控，传输过程中出问题能立刻发现。

## 8. 延迟排查

如果最终观看延迟大，按顺序排查：

| 步骤 | 测试 | 定位范围 |
|------|------|----------|
| 1 | 服务器本机 `ffplay http://127.0.0.1:25400/live/cam1.live.flv` | 上行采集/编码/ZLMediaKit |
| 2 | 外网 `ffplay http://88bill99.top:25400/live/cam1.live.flv` | 公网带宽/Nginx |
| 3 | `ffplay https://88bill99.top/live/cam1.live.flv` | TLS 开销/Nginx buffering |
| 4 | 小程序真机 | `min-cache`/`max-cache` 设置/网络 |

### 编码端确认项

- [ ] B 帧关闭（`bframes=0`）
- [ ] GOP 0.5–1 秒（`keyint` = fps）
- [ ] zerolatency 开启
- [ ] fps 固定不变
- [ ] 音频 AAC
- [ ] 码率不超过上行带宽
- [ ] 画面校正滤镜已加（`hflip,vflip`）

## 10. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| ffmpeg 连接被拒绝 | 安全组未放行 25402（RTMP） | 云控制台开放 25400–25406 TCP+UDP |
| 推流跑了几秒就断 | 网络不稳定 / 码率太高 | 降码率或降分辨率 |
| `Permission denied` `/dev/video0` | 用户不在 video 组 | `sudo usermod -aG video pi` 后重新登录 |
| 浏览器访问 25400 显示 IP not allowed | HTTP IP 白名单限制 | 编辑 `conf/config.ini` 清空 `allow_ip_range=` 并重启 |
| 小程序拉不到流 | 域名未备案 / 证书问题 | 确认 `https://88bill99.top/live/cam1.live.flv` 浏览器能打开 |
| 服务器访问 25400 超时 | ZLMediaKit 容器没跑 | `docker ps --filter name=zlmediakit` 检查 |
| 画面上下颠倒/左右反了 | 摄像头物理方向问题 | 加 `-vf "hflip,vflip"` 校正 |
| SSH 关了推流就断 | 进程挂到终端上了 | 改用 systemd 或 nohup |
| 树莓派断电后推流不恢复 | 只用了 nohup | 改用 systemd，开启 `enable` |
