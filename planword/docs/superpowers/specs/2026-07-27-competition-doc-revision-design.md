# 参赛文档修订方案

## 背景

基于严苛评委视角评审报告，对`参赛作品文档-正式版.md`进行修订。评审指出13+项问题，经讨论确认了以下修订策略。

## 核心决策

| 问题 | 决策 |
|------|------|
| 云端职责描述矛盾 | 重新定义端云边界——云端分为"传输基础设施层"和"云应用层" |
| 自主寻找未实现 | 直接删除，不保留作为功能卖点 |
| 隐私声明与实际实现Gap | 精准化隐私边界——引入"双路径"框架（行为感知路径 vs 家长看护路径） |
| 差异化时间窗口投票论证不足 | 删除具体数字（3s/2s/4s），保留机制描述 |
| 端云延迟对比数据 | 定性说明，不声称具体数字 |

---

## 一、结构性修改

### 1.1 云端职责重新分层

**目标文件**：§2.4, §4.1, 摘要，全文"云端仅处理"措辞

**修改内容**：
- §4.1 物联网架构图中，云端拆为两个子层：
  - **传输基础设施层**：ZLMediaKit流转发、Nginx HTTPS反向代理、阿里云ASR/TTS
  - **云应用层**：FastAPI + PostgreSQL + Kimi LLM + OpenClaw定时调度 + 数据分析与周报生成
- 全文统一：不再出现"云端仅处理……"
- 新叙事："云端应用层聚焦长周期数据分析、知识问答和任务调度；实时推理和行为决策全部在SC171端侧完成"
- §2.4原文"云端仅处理"改为"云端应用层负责"

### 1.2 隐私叙事精准化（"双路径"框架）

**目标文件**：摘要, §1.3设计目标, §2.4, §4.4, §3.7

**修改内容**：
- 首次出现隐私描述时（§1.3）明确区分两条路径：
  - **行为感知路径**：NPU推理后原始帧即时丢弃，不落盘不上传。上传至云端的仅为结构化行为标签。
  - **家长看护路径**：RTMP加密推流至服务器实时转发，服务器不落盘存储，家长端TLS加密播放。此路径需家长主动开启，关闭时无视频流离开设备。
- 隐私保护从"创新点"降级为"设计约束"——不再在§2中作为独立创新点出现，融入§4.4端云通信和§3.7安全保障
- 摘要中"从架构层面保护家庭隐私"→"仅上传结构化分析结果"

## 四、内容新增

### 4.1 行为分类准确率评测方法

在§3.3末尾或评测相关内容处加入：

> 行为分类准确率85%的测试条件：单儿童、室内正常光照、正脸朝向摄像头，测试集约2000帧人工标注样本，四分类（站/坐/躺/走）。该指标在多人同框、遮挡、极端光照条件下可能下降。

### 4.2 已知局限章节（移植自项目定位文档）

在§5.1完成情况后新增表格：

| 局限 | 说明 | 影响范围 |
|------|------|---------|
| 单摄像头人体检测无身份区分 | YOLOv8n仅做人体检测不做人脸识别 | 多子女家庭行为数据可能混淆 |
| 超声波避障存在死角 | 2路仅覆盖前方扇形区域 | 后退/平移需监护 |
| 双模型串行推理 | YOLOv8n+MediaPipe Pose串行，未做NPU并行优化 | NPU存在空闲等待 |
| 几何规则对极端姿态敏感 | 趴地/蜷缩/背对摄像头时关键点失效 | 异常姿态退入保守模式 |
| 端侧LLM未实际部署 | SC171适配1.5B模型已验证可行性，当前走云端Kimi | 离线无知识问答 |
| 用眼距离侧脸误差大 | 正脸±5cm，侧脸切换肩宽替代后±10cm | 侧脸时距离提醒精度下降 |

### 4.3 多儿童场景说明

在§3.3末尾加入：

> 当前行为分析算法面向单儿童场景设计。多人同框时以置信度最高的人体检测框为跟踪目标。多儿童独立画像见§5.3可扩展方向。

### 4.4 端云延迟定性对比

在§2.1中加入定性说明（不声称具体数字）：

> 端侧直出路径从行为事件触发到语音播报在SC171本地完成，无网络往返延迟；对比典型的云端API方案，网络往返通常引入数百毫秒以上的不可控延迟，使"在正确的时机提醒"变得困难。
