# 三分钟参赛视频脚本 — 基于端云协同的多模态儿童行为感知与移动早教智能体系统

## 录制准备清单

### 硬件准备
- [ ] 机器人实物（SC171 + 麦克纳姆轮底盘 + 7寸屏 + USB摄像头），充满电
- [ ] 手机三脚架/稳定器，拍摄机器人移动镜头
- [ ] 家长手机（已安装微信小程序，登录家长账号）
- [ ] 树莓派 + 云端服务提前启动，确保 WebSocket/RTMP 连接正常
- [ ] 一块干净桌面做儿童学习场景（放几本书/绘本）
- [ ] 光线充足的房间（客厅+卧室各一个场景，展示跨房间跟随）

### 软件准备
- [ ] 小程序各页面提前加载好（Dashboard、行为分析、周报、实时视频）
- [ ] 机器人六大模块首页提前缓存，触摸操作流畅
- [ ] 云端 AI 周报已生成一份（有数据可展示）
- [ ] 准备一段手机录屏（小程序操作过程）

### 拍摄设备
- [ ] 一台主摄手机（拍机器人+场景，1080P 60fps）
- [ ] 一台辅助手机（拍小程序屏幕特写，可用录屏代替）
- [ ] 自然光 + 补光灯（避免机器人屏幕反光）

## 详细脚本

### 第一段：开场（0:00-0:18）— 痛点 + 机器人自主亮相

**画面**：
- 0:00-0:04：黑屏文字「双职工家庭，3-8 岁孩子的课后陪伴，谁来补位？」（白字居中）
- 0:04-0:10：切到客厅场景——孩子坐在地垫上翻绘本，机器人从画面外自主驶入，缓缓靠近
  - **怎么拍**：侧拍全景，同时拍到孩子和机器人从远处靠近的过程
- 0:10-0:18：机器人停在孩子身旁，LED 灯带亮起蓝色呼吸灯，屏幕亮起显示首页
  - **怎么拍**：低角度近景，从孩子视角看机器人，突出"伙伴感"

**旁白**：
> "双职工家庭，孩子放学后的学习陪伴一直是个难题。平板电脑只能等孩子点击，固定摄像头只能看不能动。我们设计了一台能主动寻找孩子、实时感知行为、自主陪伴学习的移动机器人。"

---

### 第二段：自主寻找与跟随（0:18-0:50）— 展示机器人最核心的差异化能力

**Part A — 自主寻找儿童（0:18-0:34）**

**画面**：
- 0:18-0:26：机器人在客厅自主巡航——沿墙壁缓慢行驶，摄像头左右扫描寻找儿童
  - **怎么拍**：低角度跟拍机器人侧面，展示麦轮的平移和原地旋转能力，背景是家庭客厅环境
- 0:26-0:34：机器人"发现"在卧室看书的孩子——加速驶向孩子，靠近后减速停下，屏幕亮起
  - **怎么拍**：机器人第一视角（GoPro 粘在机器人顶部）+ 侧拍切换，展示"搜索→发现→靠近"的完整过程

**旁白**：
> "与固定设备不同，这台机器人具备自主寻找儿童的能力。当孩子不在视野内，它主动在家庭环境中巡航搜索。发现目标后自动靠近，进入陪伴状态。不是等孩子来找它，而是它去找孩子。"

**Part B — 主动跟随（0:34-0:50）**

**画面**：
- 0:34-0:43：孩子从客厅走到卧室拿书，机器人平移跟随——不转动车体，直接侧向平移，始终保持一臂距离
  - **怎么拍**：固定机位拍全景，同时拍到孩子移动和机器人麦轮平移，突出全向移动能力
- 0:43-0:50：特写麦轮——四个轮子独立驱动，机器人原地旋转调整朝向，始终面对孩子
  - **怎么拍**：俯拍或低角度拍麦轮特写，展示全向运动

**旁白**：
> "当孩子移动时，机器人通过人体检测框实时计算位置偏差，PID 控制驱动麦轮全向跟随——前进、后退、平移、旋转，始终保持最佳陪伴距离。孩子到哪，它跟到哪。跟随控制、人体检测、运动决策，全部在 SC171 端侧完成。"

---

### 第三段：行为感知与主动陪伴（0:50-1:30）— 端侧 AI 能力展示

**Part A — 端侧行为感知（0:50-1:10）**

**画面**：
- 0:50-1:00：孩子坐在桌前写字，机器人屏幕实时显示感知信息（后期叠加半透明 HUD 效果标注）：
  - 人体边界框（绿色）、33 个骨骼关键点连线、状态标签「坐姿·端正·专注度 85」
  - **怎么拍**：实拍孩子+机器人，后期叠加标注框
- 1:00-1:06：孩子身体逐渐前倾、头越来越低——HUD 标注从「端正」变为「前倾警告」，专注度持续下降
  - **怎么拍**：同一机位，让"行为变化"肉眼可见
- 1:06-1:10：叠加快闪文字标注「以上全部在 SC171 NPU 端侧运行，原始视频帧推理后即时丢弃，不上传云端」
  - **怎么拍**：后期叠加

**旁白**：
> "SC171 集成的 13 TOPS NPU 在端侧实时运行人体检测和姿态识别——15 帧每秒，YOLOv8n 检测人体位置，MediaPipe 提取 33 个骨骼关键点，几何规则分类器判断坐姿与专注状态。整个感知链路在 SC171 本地闭环，原始视频帧推理后即时丢弃——从架构层面保护家庭隐私。"

**Part B — 主动陪伴交互（1:10-1:30）**

**画面**：
- 1:10-1:16：孩子持续前倾，机器人 LED 灯带变为橙色，语音提醒"坐直一点哦~"
  - **怎么拍**：正面近景拍机器人屏幕+灯带，收录语音
- 1:16-1:22：孩子调整坐姿后，灯带恢复蓝色，机器人说"这样坐就对了！"
  - **怎么拍**：中景，同时拍孩子调整动作和机器人反应
- 1:22-1:26：切到机器人屏幕特写——孩子问"太阳为什么发光？"，Kimi 大模型回复文字+TTS 语音
  - **怎么拍**：屏幕特写
- 1:26-1:30：分屏：左侧机器人屏幕显示题目，右侧孩子正在点击答题
  - **怎么拍**：分屏合成

**旁白**：
> "感知之后是行动。从行为事件触发到语音播报，全链路在 SC171 端侧毫秒级闭环——不受网络影响，不依赖云端。需要知识问答时走云端 Kimi 大模型通道。端侧保证陪伴的实时性，云端提供知识的深度。两条路径由决策引擎统一调度。"

### 第四段：双向互通（1:30-2:10）— 行为事件实时推送 + 家长远程回应

这一段展示的是本系统的另一个核心创新：**不是单向监控，而是双向情感连接**。机器人感知到的行为事件实时推送到家长端，家长可以即时回应——形成从"孩子行为→机器人感知→云端推送→家长响应→机器人传递→孩子感受"的完整双向闭环。

**Part A — 行为事件实时推送（1:30-1:48）**

**画面**：
- 1:30-1:36：孩子切换学习模块——手指点击屏幕进入「数学妙算」
  - **怎么拍**：拍机器人屏幕+孩子手指操作
- 1:36-1:42：画面切到家长手机——小程序弹出实时推送通知「孩子已进入数学模块」，同时状态卡片更新：当前模块从「科学探索」→「数学妙算」，专注度实时刷新
  - **怎么拍**：手机录屏，展示推送通知弹出+状态卡片动态刷新
- 1:42-1:48：多事件时间线展示（后期叠加动画）——几个行为事件依次浮现在时间轴上：
  - 「14:02 进入科学探索，专注度 82」
  - 「14:18 坐姿前倾预警，已自动提醒」
  - 「14:25 进入数学妙算，专注度 78」
  - 「14:40 起身活动提醒」
  - **怎么拍**：后期动画，竖排时间线，事件节点带颜色标签（绿=正常，橙=提醒，蓝=模块切换），突出"家长虽然没有亲历，但对孩子的学习节奏了如指掌"

**旁白**：
> "家长与孩子之间的连接，是本系统从第一天就确立的核心设计目标。机器人在端侧感知到的每一个行为事件——进入哪个学习模块、专注度如何变化、坐姿是否有异常——都通过 WebSocket 实时推送到家长小程序。家长打开手机，看到的不是一句模糊的'在线'，而是孩子在哪个房间、在学什么、学得专不专注。哪怕不在家，孩子的学习节奏也清晰可感。"

**Part B — 家长即时回应（1:48-2:02）**

**画面**：
- 1:48-1:54：家长看到状态卡片中专注度下降，点击「发送鼓励」——选择表情「加油💪」发送
  - **怎么拍**：手机录屏，手指从状态卡片→点击发送→选择表情，操作流畅
- 1:54-1:58：机器人在学习间隙，屏幕突然弹出家长发来的「加油💪」表情（全屏显示 2 秒），灯带短暂闪烁绿色，然后自动切回学习界面
  - **怎么拍**：拍机器人屏幕，表情弹出要有"突然感"和"惊喜感"
- 1:58-2:02：孩子看到表情后笑了，坐直身体，继续答题
  - **怎么拍**：中景，捕捉孩子表情变化——这是整个视频最有人情味的镜头

**旁白**：
> "更关键的是——这不是单向监控。家长看到孩子实时状态、房间位置后可以即时回应：发送一个表情、一句语音鼓励，指令经云端 WebSocket 网关直达 SC171，端到端延迟不到 100 毫秒。抬头显示在机器人屏幕上，孩子看到的是来自爸爸妈妈的实时关心。同时，通过本地部署的 OpenClaw 平台，家长可以随时发布学习任务、设计专属题目——从被动查看到主动参与，所有数据本地处理，让家长更放心，孩子使用更安心。一个表情、一句'宝贝加油'，让孩子知道——家长一直在。这种双向情感连接，是固定摄像头和平板电脑永远做不到的。"

**Part C — 远距离的"在一起"（2:02-2:10）**

**画面**：
- 2:02-2:06：家长手机切换到「实时看护」页面，视频画面中机器人正跟着孩子移动
  - **怎么拍**：录屏，展示视频流+遥控面板同屏
- 2:06-2:10：分屏画面——左：家长手机显示视频+刚发送的 TTS 语音「宝贝继续加油」；右：机器人正在播放这段语音，孩子边听边抬头看机器人
  - **怎么拍**：双画面分屏合成

**旁白**：
> "实时视频让家长看到画面，行为事件让家长了解状态，表情和语音让家长传递温度。三者在同一个系统里闭环——这才叫真正的双向互通。"

### 第五段：行为分析与成长报告（2:10-2:47）

这一段展示系统如何将"端侧感知的碎片化行为事件"转化为"家长真正能用得上的成长洞察"。核心叙事：**从数据到洞察，从洞察到建议**。

**Part A — 从碎片事件到多维分析（2:10-2:25）**

**画面**：
- 2:10-2:17：手机录屏——小程序「行为分析」页面，专注度趋势曲线（近 4 周持续上升）
  - **怎么拍**：录屏，手指沿曲线滑动，配合数据点标注动态弹出（"第 1 周: 68""第 4 周: 85"）
- 2:17-2:22：手势切换到姿态统计饼图——坐姿端正 82%、前倾 12%、歪斜 4%、后仰 2%；下方对比卡片"上周端正率 75% → 本周 82%，+7%"
  - **怎么拍**：录屏，从曲线图自然滑动到饼图，突出"本周 vs 上周"对比设计
- 2:22-2:25：切到房间活动分布图——客厅专注度 85 分（学习时长 2.8h）vs 卧室 68 分（学习时长 0.7h），配气泡标注「客厅是更有效的学习空间」
  - **怎么拍**：录屏

**旁白**：
> "但实时数据只是第一步。系统的真正价值在于——把碎片化的行为事件，聚合为家长能读懂的成长趋势。孩子的每一次学习、每一个行为状态变化，都在云端数据库中按日、按周、按房间自动聚合。专注度是在上升还是下降？坐姿比上周改善了吗？在客厅学习效率更高还是在卧室？——这些问题的答案，不再是家长凭感觉猜测，而是有数据支撑的清晰判断。"

**Part B — AI 周报：从数字到自然语言（2:25-2:40）**

**画面**：
- 2:25-2:33：小程序「AI 周报」页面，周报从顶部缓缓下滑，逐段展示：
  - 本周总览：「本周学习总时长 3.5 小时，专注度 78 分（较上周 +15%）」
  - 行为亮点：「坐姿优良率 82%，比上周提升 7 个百分点」
  - 模块偏好：「科学探索投入时间最长，专注度最高达到 85 分」
  - 建议段落：「下午时段专注度偏低，建议搭配互动性更强的学习内容」
  - **怎么拍**：录屏，缓慢下滑，给每段留 2 秒阅读时间
- 2:33-2:40：特写周报底部的"亮点卡片"——AI 生成的总结文案
  - 「本周小明的科学探索专注度最高，是明显的兴趣方向。建议下周增加实验类互动内容，进一步激发他的好奇心。另外，下午 3 点后的专注度有所下降，可以考虑安排户外活动作为调节。」
  - **怎么拍**：录屏，停留在这个卡片上，突出自然语言的"人味"

**旁白**：
> "每周日，Kimi 大模型自动汇总当周行为数据，生成自然语言的 AI 周报。注意——这不是把数字翻译成句子，而是真正有洞察的成长分析。它会告诉你孩子在哪类学习中表现最好、什么时间段效率最高、哪个坐姿问题正在改善还是恶化。月报更进一步，展示跨月的变化趋势和学习里程碑。对家长来说，这份报告不需要任何技术背景就能读懂——因为关于孩子成长的事，本来就该用'人话'来说。"

**Part C — 成长画像（2:40-2:47）**

**画面**：
- 2:40-2:47：快切蒙太奇——同一孩子在不同时间的学习画面（3-4 张照片快速切换），最后定格在一张成长趋势总览图（蜘蛛图：专注度、坐姿、学习时长、知识广度、坚持力五维雷达图）
  - **怎么拍**：后期合成，照片+雷达图淡入叠加

**旁白**：
> "一天的数据是快照，一周的数据是报告，一个月的累积才是真正的成长画像。这就是我们想给每个家庭的——不是一台冷冰冰的机器，而是一段有温度、有数据、有方向的成长陪伴。"

## 录制技巧速查

| 场景 | 怎么拍 | 注意事项 |
|------|--------|---------|
| 机器人自主巡航 | 低角度跟拍/侧拍 | 地面干净，光线充足，展示家庭环境 |
| 机器人跟随孩子 | 固定全景机位 | 同时拍到孩子移动和机器人响应 |
| 麦轮特写 | 俯拍或低角度近景 | 展示独立转动能力 |
| 屏幕特写 | 手机贴近屏幕，对焦锁定 | 关闭屏幕自动亮度，调到最亮减少频闪 |
| 小程序操作 | 录屏为主，手指慢且稳 | 提前关闭通知弹窗，网络信号满格 |
| 语音交互 | 现场收音 + 后期字幕 | 环境安静，机器人音量调大 |
| HUD 标注叠加 | 后期合成（AE/剪映） | 绿色框+白色文字，半透明底色 |
| 分屏对比 | 后期合成 | 留好安全边距，两侧画面比例一致 |

## 后期要点

1. **配音**：男声或女声均可，语速中等偏快（约 190 字/分钟），3 分钟对应约 570 字旁白。语调专业但不生硬，有讲述感
2. **BGM**：轻快科技感背景音乐（如 Lo-fi beats / 轻电子），音量低于旁白 6-8dB
3. **转场**：段落间用 0.5s 渐黑或平滑推入，不要用花哨转场
4. **字幕**：底部中文字幕，关键技术术语（SC171、NPU、YOLOv8n、MediaPipe、WebSocket、RTMP、Kimi）首次出现时加英文标注
5. **HUD 标注**：行为感知段落的关键叠加标注需提前设计模板（绿框+关键点连线+状态标签），与视频画面比例一致
6. **Logo**：右下角放入项目 Logo 水印，全程可见
