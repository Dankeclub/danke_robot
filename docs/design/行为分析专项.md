# 0622 行为分析专项

> 基于《0622 细节讨论纪要》整理。聚焦行为识别与分析，已删除小车控制等无关章节。长期数据挖掘部分由专家补全，团队据此填库与设计报告页面即可。
> 整理日期：2026-06-25

## 1. 项目定位

- **核心是行为分析，不是早教。**
  儿童应用只是行为分析的一个落地场景。早教本身作为卖点没有意义——只是让家长觉得"买这个东西能实现教育目的"从而愿意付费。实际上产品的本质价值是**让家长放心**。
- 行为分析不需要做得极端精准，或者说**准不准确区别不大**——现场演示时不可能让人等着看完"在客厅看几分钟电视"这样的全量轨迹，能展示的只是几分钟内的实时识别。

## 2. 实时识别 vs 历史分析:生产和消费的边界

### 2.1 实时识别(现场给人的能力证明)

- 演示时能够实时识别的行为:**看书、玩游戏、看电视、心不在焉**等。
- 这部分**做不了假**——代表的是识别能力的真实性。误报率不能太高。
- 技术路线:**MediaPipe**,或 **MediaPipe + YOLO**。具体特征工程见 §4.1。
- 现场演示的"诚实姿态"——只承诺识别"当下在做什么",不承诺"理解为什么这么做"。前者是几秒可验证的,后者要靠长期数据,不应在现场叫板。

### 2.2 历史分析与报告(数据挖掘,需要入库)

- 链路:MediaPipe 行为识别 → 行为思维分析 → **入库** → 第二天消费昨日数据。
- **生产与消费不对等**:
  - 昨日数据已全部入库,可以**全量消费**(统计分析、趋势挖掘)。
  - 当日实时数据没有结束,只能看到"截止当前他干了什么",不能马上做完整分析。
- 举例:每 2 分钟报一次"在看电视" → 统计多少个 2 分钟 → 串成时间片。这种统计**必须有完整一天甚至一周的轨迹数据**才能得出趋势性结论。
- 报告定位:**长期主义观测**——不是抓到孩子走神一两分钟就推送给家长,那是**不负责任的**。要做的是发现长期存在的**共性问题**。
- 详细字段设计、聚合层级与报告结构见 §5。

### 2.3 辩论话术(应对质疑)

- 如果有人说表情识别/情绪识别不准 → 不要争辩,直接承认:**"确实有问题,但我们只是把它作为数据来源之一,并没有据此判断孩子不认真。"**
- 然后转折:**"我们后面有自己的一套深度学习算法,综合评估孩子每天的情绪状态,最终生成报告。"**
- 核心逻辑:单点数据只是输入 → 不直接做判断 → 综合长周期数据后才出结论。

## 3. 比赛演示策略:什么做真、什么可模拟

### 3.1 必须真实的部分

- **实时行为识别**:演示现场几秒钟内识别出当前行为。这是别人看得到、能验证的。

### 3.2 可以模拟的部分

- **历史报告数据**:数据来源是数据库。对于比赛来说,**数据库里造假数据无法被证伪**。报告模板和数据库字段提前设计好,日期范围内填充即可。
- 类比:面包店——做面包的人不是直接把面包递到你手上,而是先放到货架上,你再从货架上挑。

### 3.3 取舍原则

- 实时识别先做实事。
- 历史报告后面再补——**临时搓静态页面都能展示**。
- 如果不是做真产品,这个 gap 对比赛足够;如果是真产品,这个 gap 绕不过去。

## 4. 实时识别技术细节

### 4.1 行为识别链路与特征工程(专家补全)

#### 4.1.1 整体链路

```
摄像头帧 → 抽帧 → MediaPipe(骨架+脸+手) → YOLO(物体:屏幕/书本/玩具) →
特征向量 → 规则/小模型分类 → 多帧投票 → 行为标签+置信度 → 入库
```

- AI 模型**不是每秒都在算**(考虑续航),而是**抽帧**:
  - **演示模式**:1~2 fps,保证现场观感(几秒内出结果)。
  - **日常模式**:每 30 秒~4 分钟抽 1 帧,平板/小车续航优先。
- MediaPipe 与 YOLO 的分工:
  - **MediaPipe**——出 33 个身体关键点 + 468 个面部点 + 21×2 只手关键点。提供**姿态/视线/手部动作**这类"人怎么动"的信号。
  - **YOLO**——出"环境里有什么":屏幕/电视、书本、玩具、桌面、零食。提供**人在跟什么交互**的信号。
- 两者**必须组合**才能区分行为:同样是"低头",看书 vs 玩手机靠 YOLO 区分;同样是"面对屏幕",看电视 vs 玩游戏靠手部动作频率区分。

#### 4.1.2 四种核心行为的判定特征

| 行为标签 | 关键判定特征 | 必要信号 | 易混淆/误报源 |
|---|---|---|---|
| **看书** | 头部俯角 15°~45°、视线下方、YOLO 检出书本且与手部 ROI 重叠、手部低频翻页动作 | 头部姿态 + 书本检出 | 低头玩手机(用 YOLO 区分手机 vs 书本) |
| **玩游戏** | 面对屏幕、视线锁定屏幕区域、**手部高频微动**(每秒>2 次)、躯干前倾 | 视线 + 手部动作频率 + 屏幕检出 | 看电视(手部静止)、打字学习(同样手部高频,靠屏幕内容/坐姿区分,演示场景一般不要求区分) |
| **看电视** | 面对屏幕方向(可不是平板屏)、视线锁定、**手部静止**、身体放松/后仰 | 视线 + 手部低活动度 + 屏幕检出 | 玩游戏(手部活动度区分)、发呆面向电视方向(视线锁定 vs 涣散) |
| **心不在焉/走神** | 视线方向变化频繁、头部朝向偏离任务区(书/屏)>30°、躯干扭动、长时间无任务相关动作 | 视线方向方差 + 头部朝向偏离 | 短暂转头(用窗口时长过滤,见下) |

#### 4.1.3 多帧投票与置信度策略(控制误报的关键)

单帧判定噪声大,必须做时间窗口聚合:

- **滑动窗口**:30 秒为一个判定窗口,窗口内每帧投票。
- **多数投票 + 置信度阈值**:某行为标签在窗口内占比 ≥ 60% 且平均置信度 ≥ 0.65 才输出。否则输出"不确定"(不入库或入库标记为 `uncertain`)。
- **状态平滑**:相邻窗口标签切换需"连续两个窗口同意新标签"才切换,避免抖动。
- **走神的特判**:走神是"持续状态",窗口要拉长到 60~90 秒,避免把"翻页时短暂抬头"判成走神,这是误报最伤口碑的一种。
- **置信度入库**:每条记录带 `confidence` 字段,报告侧只用 `confidence ≥ 0.7` 的数据做统计,低置信数据保留但不影响结论。

#### 4.1.4 现场演示的诚实边界

- **可现场识别**:看书 / 玩游戏 / 看电视 / 心不在焉这四类大行为标签。
- **不可现场识别(明确说"长期数据才能给"))**:认真程度评分、情绪状态、注意力曲线、专注力等级——这些是 §5 长期挖掘的产物,不要在现场承诺秒级识别,容易被问倒。

### 4.2 抽帧后入库格式

抽帧后每条原始事件按 §5.1 的 `behavior_events` 表结构入库。原始关键点不入主表,如需复盘留 JSON 字段或独立日志。

## 5. 长期数据挖掘:字段、聚合、报告(专家补全)

> 这一节是给团队照着填库 + 设计报告页用的。字段先满足比赛演示,同时给真产品留扩展空间。

### 5.1 数据库字段设计

采用**四层架构**:原子事件 → 时间片聚合 → 日报快照 → 周报快照。前两层从识别结果产出,后两层是离线计算的物化结果,报告页直接读后两层。

#### Layer 1: `behavior_events` (原子事件,每次识别窗口输出一条)

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint pk | 自增主键 |
| `child_id` | varchar(32) | 孩子标识 |
| `device_id` | varchar(32) | 平板/小车设备 ID |
| `ts_start` | datetime | 窗口起始时间 |
| `ts_end` | datetime | 窗口结束时间 |
| `duration_sec` | int | `ts_end - ts_start`,冗余字段方便统计 |
| `behavior` | enum | `reading` / `gaming` / `watching_tv` / `distracted` / `uncertain` / `away`(离开镜头) |
| `confidence` | float | 0~1,见 §4.1.3 |
| `emotion` | enum | `neutral` / `focused` / `bored` / `excited` / `frustrated` / `unknown`(单点输入,不直接定性) |
| `emotion_confidence` | float | 0~1 |
| `context_object` | varchar(32) | YOLO 主要交互物体:`book` / `tablet` / `tv` / `toy` / `none` |
| `posture_score` | float | 0~1,坐姿端正度(头部俯角+躯干角度综合) |
| `source` | enum | `tablet` / `car_follow`(平板看到 vs 小车跟随看到) |
| `raw_features` | json | 可选,存关键点摘要、视线向量等,用于事后复盘 |

> 入库节奏:每个 30 秒窗口出一条;走神类窗口拉到 60~90 秒。一天单孩子约 1000~2800 条,体量很小。

### 5.2 数据挖掘维度(报告页可视化能算出什么)

从 Layer 2/3/4 能直接算出以下维度,每个维度对应一种或多种图表:

| 维度 | 说明 | 用什么图 | 数据源 |
|---|---|---|---|
| **每日行为时长分布** | 看书/游戏/电视/走神各占多少分钟 | 堆叠条形图 / 环形图 | daily_reports |
| **一天内的专注力曲线** | 横轴小时,纵轴专注率 | 折线图 | behavior_slices 按小时聚合 |
| **专注峰谷时段** | 一天中最专注/最走神的时段 | 标注 + 文字 | daily_reports.peak_focus_hour |
| **行为切换频率** | 一天切换多少次行为(浮躁度) | 单值卡片 + 周对比 | daily_reports.behavior_switch_count |
| **最长专注片段** | 当日最长连续不走神的分钟数 | 单值卡片 | daily_reports.longest_focus_streak_min |
| **情绪占比** | 中性/专注/无聊/兴奋/沮丧 | 环形图 | behavior_events 聚合 |
| **坐姿评分趋势** | 一周坐姿评分变化 | 折线图 | daily_reports.avg_posture_score |
| **工作日 vs 周末** | 专注率差异 | 双柱对比 | weekly_reports.weekday_vs_weekend_focus |
| **周趋势对比** | 本周 vs 上周专注率 | 折线/箭头 | weekly_reports.focus_ratio_trend |
| **共性问题识别** | 跨多日重复出现的问题模式 | 文字列表 | 见 §5.3 |

### 5.3 共性问题识别(报告的核心价值)

"长期主义观测"意味着不能抓单次表现下结论,要找**跨多日重复出现的模式**。以下是 7 条可直接用规则识别的共性问题,周报里按"命中天数 ≥ 3"输出:

| 共性问题 | 触发规则(基于 daily_reports / behavior_slices) |
|---|---|
| **晚间专注力崩塌** | 连续 ≥3 天,20:00 后专注率比白天均值低 30% 以上 |
| **游戏时间超标** | 连续 ≥3 天,gaming_min > 60 |
| **学习时易走神** | reading 时段内 distracted 切入比例 ≥ 25%,连续 ≥3 天 |
| **坐姿持续不良** | avg_posture_score 连续 ≥5 天 < 0.5 |
| **行为切换过于频繁** | behavior_switch_count 连续 ≥3 天位于全人群 P80 之上 |
| **情绪低迷期** | negative_emotion_ratio 连续 ≥3 天 ≥ 0.3 |
| **周末作息紊乱** | 周末 distracted_min 比工作日均值高 50% 以上 |

> 这些规则全部基于聚合层数据,**离线 SQL 就能算出**,不需要训练任何模型。比赛演示完全够用。

### 5.4 报告结构(日报 / 周报)

#### 日报结构(每日 8:00 离线生成,推送昨日报告)

```
昨日总览
├─ 观测时长:Xh Ymin
├─ 主导行为:看书 Xmin / 游戏 Xmin / 看电视 Xmin / 走神 Xmin (环形图)
├─ 专注率:XX%  (相比近 7 日均值 ↑/↓ X%)
└─ 主导情绪:专注

一天的专注力曲线 (折线图,小时粒度)
└─ 高峰:9-10 点  谷值:15-16 点

亮点
├─ 最长连续专注:XX 分钟 (位于 9:30-10:15)
└─ 完成 X 次专注阅读片段

值得关注
├─ XX:XX-XX:XX 出现 XX 分钟连续走神
└─ 坐姿评分较前日下降 X%

(注:本报告基于多帧综合判断,单点数据不作为评价依据)
```

#### 周报结构(每周一 8:00 离线生成,推送上周报告)

```
本周总览
├─ 日均观测:Xh Ymin
├─ 周专注率:XX%  (vs 上周 ↑/↓ X%,趋势箭头)
└─ 最佳一天:周X / 最弱一天:周X

本周关键发现(共性问题模块,最多展示 3 条)
├─ 晚间专注力崩塌:连续 4 天 20:00 后专注率低于白天 35%
├─ 学习时易走神:看书时段走神切入占比 28%
└─ ……

每日行为时长堆叠图 (周一~周日)
工作日 vs 周末对比 (双柱)
情绪分布趋势 (周线)
坐姿评分趋势 (周线)

下周建议(模板化,与共性问题一一对应)
├─ 建议将需要专注的学习活动安排在上午
├─ 阅读时可尝试 15+5 番茄钟节奏,降低走神切入
└─ ……
```
