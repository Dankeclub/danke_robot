既然你还没有推流，这就解释了为什么程序运行后可能看不到画面或者一直显示“连接中”。现在的逻辑链条是这样的：

从你的截图来看，命令执行后**什么都没有输出**，这说明你的 Windows 本地电脑上确实没有运行 `go2rtc`。

由于你的摄像头是**插在树莓派上的 USB 摄像头**，整个链路的源头就在树莓派上。因此，**你必须先进入树莓派的终端。**

### 为什么必须在树莓派上操作？

因为 USB 摄像头物理上连接在树莓派上，Windows 电脑和云服务器是无法直接读取到这个摄像头的。你需要：

1. 在**树莓派**上运行 `go2rtc`（或者 ffmpeg），把 USB 摄像头的数据读取出来。
    
2. 树莓派将画面转化为 **RTSP 视频流**发射出去。
    
3. 云服务器上的 **Python 代码**去拉取这个 RTSP 流进行 MediaPipe 推理。
    

### 第一步：登录到你的树莓派终端

在你的 Windows PowerShell 窗口中，使用 SSH 登录树莓派（假设你知道树莓派的 IP 和密码）：

Bash

```
ssh pi@树莓派的IP地址
```

_(注：如果你的用户名不是 pi，请替换为实际的用户名)_

登录成功后，你会发现前面的提示符从 `C:\Users\danke>` 变成了类似 `pi@raspberrypi:~ $` 的样子。

### 第二步：在树莓派上配置并启动 USB 摄像头推流

进入树莓派后，由于是 USB 摄像头，`go2rtc` 需要调用底层驱动（通常是 `v4l2`）。

1. **检查树莓派是否识别了摄像头**：
    
    Bash
    
    ```
    ls /dev/video*
    ```
    
    如果能看到 `/dev/video0`，说明摄像头硬件正常。
    
2. **配置树莓派上的 `go2rtc.yaml`**：
    
    在树莓派下载好 go2rtc 后，在其同级目录下创建或修改 `go2rtc.yaml`，填入以下针对 USB 摄像头的配置：
    
    YAML
    
    ```
    streams:
      camera1:
        - ffmpeg:device?video=/dev/video0&input_format=mjpeg&video_size=640x480#video=h264
    ```
    
    _(注：这里使用 ffmpeg 将 USB 的 MJPEG 格式实时编码为 H264 供网络传输，分辨率设为 640x480 可以大幅降低树莓派的编码压力和延迟。)_
    
3. **在树莓派上启动它**：
    
    Bash
    
    ```
    ./go2rtc_linux_arm64  # 注意树莓派通常是 arm64 或 arm 架构的文件
    ```
    

### 第三步：验证树莓派推流是否成功

当树莓派上的 `go2rtc` 跑起来后：

- 在你的 **Windows 电脑浏览器**中输入：`http://树莓派的IP:1984`。
    
- 如果能看到 `camera1` 并且能点开看到画面，说明**树莓派端推流成功**！
    

接下来的地址就是 `rtsp://树莓派的IP:8554/camera1`，你就可以把这个地址填进云服务器的 Python 代码里去跑了。
